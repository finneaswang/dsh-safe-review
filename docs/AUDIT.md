# 0.2.0 独立审核增量审计

日期：2026-10-11。0.1.0 固定版本的审计记录保留在后半部分；其中模型权限与覆盖范围已由本节和 README 更新。

## 研究及复用

开发阶段复核了官方 Auto Review 与社区候选，下面的固定提交链接和第三方说明记录了采用的基础。继续使用 NanmiCoder 的 MIT 路径/Shell 分析基础和已经验收的官方 guard。参考 [aa2246740/dsh-auto-review v0.4.2](https://github.com/aa2246740/dsh-auto-review/tree/bd6c8df214f525488afd1bdcb05469ab88fb3a6a) 的独立 reviewer 路由、无工具审核与故障转人工思路，没有复制其源码。

目标固定为 DSH 0.2.0-rc.2 / Cordis 4.0.4；其他插件标注兼容不等于本机实际通过。官方实验功能的 dispose 分支会迁移预设，不据此推断所有版本的重启都有问题。

## 新授权链

1. 本地规则先拒绝已识别高风险，敏感和不透明行为保留人工底线。
2. 官方 host-only projection 收集有 RPC 来源标记的人类输入，保留早期限制。新输入入队即使还未进入模型步骤也使旧审核失效。工具、助手、合成消息及子代理不能提供人类授权。
3. 独立模型通过 OpenAI Responses API 读取完整证据；请求设固定域名、禁止重定向、无工具、严格输出和总时限。不截断后批准。
4. 请求前跨进程锁定并持久化预算预扣；有效用量才结算。网络未知结果保留扣额，UTC 日期倒退、坏账本、残留锁均转人工。
5. 明确 low/allow 才能建立单次执行凭据；模型拒绝立即停止，其他结果走原生人工窗口。后续宿主策略的 ask/deny 始终保留。
6. 最终 guard 重新验证参数、权限、路径、人类上下文版本和调用身份。只消费一次；重启不会恢复许可。

本机正常项目密钥仅由专用文件读取。权限、所有者、符号链接和硬链接校验阻止错误引用；不读取或复用 Admin Key。预算与密钥路径加入本地保护。模型提供方不可配置为任意 URL。

## 明确边界

模型评估与确定性门禁是两层：模型可能认为一个项目测试可以允许，门禁仍能因脚本内容未被核验要求人工。命令行本身不足以证明内部脚本行为。普通插件不能建立同进程恶意插件的安全隔离，也无法保证卸载之后仍有保护。

Browser 简单导航的参数审核不等于对 DNS、重定向或页面实际效果的网络隔离；通用点击、Computer Use、MCP 及 PTC 容器仍由原生窗口确认。没有声称完成所有真实服务的副作用测试。

`store:false` 不替代 OpenAI 组织的数据共享设置；本地 token 账本也不是账户免费额度查询。真实 API 测试仅发送合成场景，相关结果与 Desktop 实测分别记录。

日期：2026-10-10（America/Vancouver）。目标：macOS arm64，DSH Desktop 0.2.0-rc.2。

## 一手来源与复用选择

1. [官方 DSH 固定发行源码](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84)。核对了 `packages/core/tools`、`interaction/user-approval`、`interaction/permission-presets`、`experimental/auto-review`、`sandbox/sandbox-policy`、`fs/fs-sandbox`、`api/remotes` 与 `apps/cli`。实际安装应用的归档元数据也确认了 DSH 0.2.0-rc.2 和 Cordis 4.0.4。
2. [NanmiCoder/dsh-auto-mode 固定源码](https://github.com/NanmiCoder/dsh-auto-mode/tree/907d663b7d65e3fcd9f328c598dee03772cac18b)。版本 0.2.0，MIT。该项目已宣布结束维护。其 sandbox-auto 方案与目标版本吻合，因此复用了路径、Shell 风险熔断、补丁解析、分类器传输及对应回归测试；未启用其宽松自动允许策略。完整来源、许可证和修改项见 THIRD_PARTY_NOTICES。
3. [PerryLink/dsh-auto-review 固定源码](https://github.com/PerryLink/dsh-auto-review/tree/2b931b8375f9ee9ebe20e80ef336c69804e1aac0)。版本 0.12.17。读取了审批接入、策略、审计与 reviewer 隔离代码。未复制其 Apache-2.0 代码；本实现不依赖它。其当前依赖线包含更新的 DSH alpha 版本，不能将仓库声明等同于对本机版本的实测兼容性。

## 与要求有关的发现

| 实现 | 源码观察 | 本次选择 |
|---|---|---|
| 官方实验性 Auto Review | 当前会话身份使用 `danger-full-access + ask`；模型可允许具备授权的 medium 风险动作 | 不采用这种执行模式 |
| Sandbox Auto | 保持 workspace-write；但默认允许大量普通／未知 Shell 和工具，模型可批准单次扩权 | 复用解析与熔断代码，替换自动允许路径 |
| 第三方 Auto Review | 回答 `approval/request`；仅审批请求会经过此入口 | 使用 `tools/pre-execute` 加最终 guard，覆盖未主动请求审批的工具 |
| 官方审批服务 | `allowed-once` 本身不证明答复来自人类，插件也能返回这个值 | 检查当前回答器的官方模块函数身份，拒绝额外回答器 |
| 官方工具管线 | pre-execute 后有只可否决的 monotonic guard；参数和执行 token 由宿主管理 | guard 校验独立的单次凭据，防止监听器短路绕过 |
| 卸载／加载失败 | 宿主插件是可移除的；插件无法在被移除后继续执法 | 不写宽权限状态；明确要求安装检查与停止会话后卸载 |

这些是针对固定版本的观察，不是对后续版本的保证，也不是上游漏洞披露。插件之间共享 Node 进程的信任模型，是本实现无法突破的限制。

## 执行顺序

1. 校验 Agent、当前 sandbox 与审批策略；Full access、无人归属的调用和异常父会话策略被阻断。
2. 完整参数做本地规则判断。关键配置／系统破坏等明确高风险拒绝。低风险仅限已适配的普通工作区文件操作。
3. 调用后续政策监听器，保留其拒绝／取消；其人工要求不能被本插件自动降级。
4. 对需要确认的操作，可选模型只提供限制性意见。脱敏或截断过的证据不能支持自动授权；任何模型允许仍受本地人工门槛约束。
5. 通过官方 ApprovalService 请求本次人工决定，使用原生 asked/decided 审计事件；检查回答器来源、取消与期限。
6. 建立内存中的单次凭据。最终 guard 在工具主体之前再次核对权限、参数、路径风险、Agent 与 token，并消费凭据。没有凭据即拒绝。
7. 进程退出、插件重载或调用结束后不复用授权。使用官方既有日志类型，避免自定义持久事件造成会话恢复不兼容。

## 审计中修复的问题

- 扩权参数可能先于受保护路径检查：调整为关键路径拒绝始终优先。
- 通过符号链接把普通名称指向配置：增加真实目标检查；禁止通过符号／共享硬链接写入。
- 模型不遵守 AbortSignal 时可能无限等待：增加独立计时截止，返回人工确认。
- 审批系统可能被另一自动回答器抢答：验证官方 Remote 回答器，拒绝混合审批链。
- 打包验收夹具遗漏服务注入声明：通过真实 CLI 启动暴露并修复，未用模拟器掩盖加载失败。

## 有意保守的限制

Browser／Computer Use／任意 MCP／终端目前都需逐次人工确认。MCP `readOnlyHint` 和名称中出现 read 不等于效果证据。Shell 的函数、环境、启动文件、持久状态和脚本内容使静态自动允许难以成立。后续扩展应逐个接入有完整效果语义的操作适配器，再添加对应反例测试。

通用 Browser、Computer Use 和 MCP 工具的拦截已在真实工具管线上用无副作用的工具主体测试；未在本次交付中操纵真实账户、真实 MCP 服务或现有 Desktop 窗口。可选模型路径使用固定响应与故障注入测试，未进行真实模型准确率评测。
